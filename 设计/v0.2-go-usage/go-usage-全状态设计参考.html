设计基调：两个数据源（本地 SQLite / 官方额度 API）独立加载、独立降级、互不阻塞。 任何一个失败只降级自己的区块，另一区块照常工作。反馈统一用顶部 banner（沿用现有 widget 模式，不引入 toast—— 悬浮窗常驻场景下 toast 会打断感，banner 可常驻直至恢复）。

边界场景处理规则
长模型名deepseek-v4-flash-vision-exp（27 字符）、muse-spark-1.3-contributor 列表行 CSS ellipsis 截断 + title 悬浮全名；CLI 列宽按最长名 +2 自适应，超 22 字符截断为 deepseek-v4-flash-v…
大数字请求 26,991；token 6.41B；$168.99 窗口：请求数 ≥10,000 千分位逗号；token 沿用 k/M/B；费用两位小数。CLI：请求数千分位，token k/M/B，费用两位小数
percent 边界0% / 1% / 99% / 100%（未限流） 0% 渲染 2px 最小可见条；100% 但 status=ok（卡点但未触发限流）用 hit 红但不显示 banner——banner 只跟 status 走
倒计时边界resetsAt <60s；已过期（时钟偏移） <60s 显示"即将重置"；resetsAt < now 显示"等待刷新"并在下个轮询周期修正；5h 倒计时格式 2h11m，<1h 38m
重置时点月 1 号 / 周一 00:00 UTC resetsAt 以服务端为准直接格式化为日期（本地时区），不自行推算周期边界
token 全 0模型返回空响应（kimi-k2.7-code 仅 1 次请求 0 token） 该模型照常进列表（请求数 1）；命中率分母含 0 时该项显示 "—"；CLI 柱宽 0 → 最小 1 字符
API key 明文key 存 auth.json 明文 只读内存传递，不写入日志、不进 --json 输出、错误信息不含 key；--json 的 quota 段只有 percent/status/resetsAt
系统休眠唤醒笔记本合盖过夜 唤醒后轮询计时器自然触发下一次；不补拉错过的周期；generatedAt 更新为最新

S9 · 交互行为规则表

触发用户操作系统行为反馈
系统启动运行 npm run widget 读 auth.json（识别 opencode-go 凭据）→ 打开窗口 → 并行：①本地 DB 汇总 ②额度 API（若凭据存在） 首屏 <1s（本地区），额度区 skeleton 直到返回或 8s 超时进 S3/S4
系统每 30s— 重查本地 DB（readOnly），推送 usage:update 数字平滑更新，无闪烁、无布局跳动；时间戳更新
系统每 5min— 调 GET /zen/go/v1/usage；连续 ≥3 次失败 → 退避至 15min 额度三条更新；恢复后立即回到正常渲染
用户切 Tab点击 费用 | Go 切换 pane（互斥渲染）；banner 状态两 tab 共享 tab 高亮迁移；数据不重拉（内存共享）；<50ms
用户刷新点击 ↻ 立即重查本地 DB + 穿透额度缓存重调 API 图标旋转 420ms；两区数据即时更新；额度失败时区内文案更新
用户关闭点击 ✕ ipc widget:close → 销毁窗口 → 清理定时器 → 进程退出 窗口消失，无残留进程
系统凭据变化用户中途在 opencode.ai/auth 订阅或换 key 监听 auth.json mtime 变化 → 重读凭据 → 若 S4 态则重试 API 一次 额度区从"未检测到订阅"恢复为三窗口（或维持失败文案）
异常额度 401/403— 标记 quota 不可用（reason: no-subscription）；停止轮询，改为 mtime 触发 S4 渲染；header 圆点变灰；本地区照常
异常额度网络失败— 标记 reason: network；保留 lastGood 快照；退避轮询 S3 渲染（含"上次成功"锚点）
异常rate-limited— status != ok 的窗口条置红；组织 banner 文案（含倒计时） S5 渲染；重置窗口到点后下次轮询自动解除
异常DB 不可用— local.available=false；30s 重试 S6 渲染；琥珀 banner 常显直至恢复
异常CLI --quota 失败显式请求额度 打印失败原因 + 上次成功锚点；退出码仍 0（数据获取成功，额度为空属正常分支） 见 S8.2/8.3 文案

S10 · 反馈规范（banner，widget 无 toast）

决策：widget 全部反馈走顶部 banner（现有 widget 模式），不引入 toast。理由：悬浮窗常驻、面积小，toast 会遮挡内容且消失即失忆； banner 可常驻至状态恢复，与"监控工具"心智一致。CLI 反馈 = 终端文案 + 退出码，无 toast 概念。
文案样式出现时机消失时机
"Go 已达 5 小时上限 · 重置后自动恢复 · 期间可切免费模型（opencode/*）"红 banner 任一窗口 status=rate-limited下次轮询该窗口 status=ok（倒计时同步显示在 banner 内）
"本地数据库不可用，等待中…（每 30s 重试）"琥珀 banner DB 缺失/不可读首次读取成功
"额度数据不可用" / "未检测到 Go 订阅"仅额度区内文案，不上 bannerS3 / S4API 恢复 / 凭据出现
"额度数据不可用：<reason>（上次成功 HH:MM，月 N%）"CLI 文案CLI 额度失败—
规则：同时最多 1 条 bannerrate-limited 优先于 DB banner（影响工作流的排前）；两条同发时合并为一条红 banner 分行显示
