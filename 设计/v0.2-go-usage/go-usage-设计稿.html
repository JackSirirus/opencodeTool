CLI 规格
  • 命令：node bin/opencode-usage.js go（= npm run usage -- go），与 today/week/all 同级。
  • 额度区（violet）：三条窗口 + 限额参考值（$12/$30/$60）+ 重置时间。percent 直接展示 API 返回值，不换算美元余额（API 不返回金额，issue #41981 仍 open；换算会因模型乘数失真）。
  • 额度数据获取：读 auth.json → opencode-go.key，Bearer 调 /zen/go/v1/usage。失败（离线/无 key/403 无订阅）→ 额度区显示一行"额度不可用：<原因>"，退出码仍 0。
  • status=rate-limited：该行红色 !! 前缀 + percent=100，尾部提示"可切换免费模型（opencode/*）"。
  • 模型表：全量按请求量降序（--sort cost 可选）。柱宽按请求量归一化。
  • 命中率双口径：占输入 = cacheRead/(input+cacheRead+cacheWrite)；读写占比 = cacheRead/(cacheRead+cacheWrite)。今日+累计两列。
  • JSON：--json 输出 {local, quota} 两段——local 来自数据层 getGoUsage()，quota 来自 API（成功时含三窗口对象，失败时 null + reason），供小窗口复用。

③ Go 套餐额度规则速查（opencode.ai/docs/go/，2026-09-07 版）

  • 订阅：$10/月。限额按美元价值计：5 小时 $12 / 每周 $30 / 每月 $60。
  • 有效额度因模型而异：每个模型有独立月额度乘数（如 MiMo-V2.5 $60 ≈ 15 万请求/月；DeepSeek V4 Pro $15 ≈ 5,200/月；Omen Alpha $100）。因此同一 percent 在不同模型下含义不同，UI 不做"剩余请求数"换算，只展示服务端 percent。
  • API 权威：GET /zen/go/v1/usage（Bearer key）→ {usage: {rolling/weekly/monthly: {status: "ok"|"rate-limited", percent: 0-100, resetsAt}}}。错误：401 AuthError（key 无效）、403 EntitlementError（无 Go 订阅）。不返回美元金额/余额。
  • 超限行为：开启 "Use balance" → 回退 Zen 余额继续；否则阻止请求。免费模型（providerID=opencode）始终可用。
  • 价格参考：DeepSeek V4 系分峰谷（peak = 周一至五 01:00–04:00、06:00–10:00 UTC，其余 off-peak，价差 2 倍）——解释本地 cost 标记波动；UI 不标注峰谷（复杂度不值）。
  • 轮询纪律：端点每次查询是服务端三表 join，社区建议 ≥5min 缓存；端点无 Cache-Control / X-RateLimit 头。实现用 5min 定时 + 手动刷新穿透。
